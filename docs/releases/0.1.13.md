# 0.1.13 — подтверждения исполнения LBank из приватного потока

Локальная версия от 2026-09-07. В production-каналы не опубликована.

Наблюдавшийся сбой: принятая заявка BTC `1008009397092400` исчезла из списка активных, но отсутствовала в REST-истории и точном запросе исполнений. Свежая позиция при этом читалась. Ответы приходили по сети с `Cache-Control: no-store`; смена фильтров на параметры публичного клиента не вернула пропущенную заявку. Повторная сверка 0.1.12 ожидала историю и при восстановлении входа ошибочно пыталась закрыть первую ногу.

- При подключении профиля устанавливается пассивный наблюдатель существующего приватного потока LBank. Сохраняются точные ID, монета, сторона, исходный и исполненный объём, статус и цена. Новые сетевые подписки не создаются.
- Терминальные события остаются в ограниченном кеше страницы после удаления заявки из активного списка. Привязка к соединению и аккаунту, проверка объёма/стороны и защита от устаревшего `NEW` исключают подмену подтверждения соседней заявкой. Противоречивые терминальные данные требуют сверки.
- При отсутствии цены терминального исполнения REST не может обнулить подтверждённый объём. Цена дополняется точными исполнениями; лимитная цена не выдаётся за цену сделки.
- Без доступного наблюдателя новый вход блокируется до переподключения профиля. Явное закрытие только для уменьшения позиции остаётся доступным.
- Восстановление входа сверяет прежние ID, подтверждает окончательный объём первой ноги и достраивает только недостающий объём второй. Повторного входа или автоматического закрытия первой ноги из-за задержки истории нет. Частично исполненный вход может остаться меньшим равным хеджем в рамках прежнего бюджета. Stop всегда запрещает продолжение входа.

259 backend-тестов проходят, включая полный изолированный цикл вход → хедж → закрытие через настоящий адаптер с пустыми REST-списками и подтверждениями только из потока, недоступный наблюдатель, противоречивые статусы, частичные исполнения и Stop во время сверки. Production-сборка включает проверку TypeScript.

На запущенном профиле пользователя наблюдатель установлен (`ready`). Для вручную открытого короткого BTC-объёма 0,0012 проверены свежий снимок, доступное количество, точный селектор позиции и подготовка `BUY / MARKET / reduceOnly` на 0,0012 с корректным `PosiDirection`. В диагностике вызов отправки заменён возвратом подготовленных параметров; реальный ордер средствами разработки не отправлялся.

Затем фактическое закрытие этой тестовой позиции было подтверждено приватным событием `1008009409378552`: `FILLED`, BUY 0,0012 BTC по 79 045,1. Новый SDK прочитал точные данные из наблюдателя с `confirmationSource=private_stream`; свежий список BTC-позиций пуст. В запущенной пользователем сессии 0.1.13 также подтверждены обе ноги BNB по 0,26, состояние `running`; повторные исходные лимитки имеют точные отменённые ID с нулевым исполнением, единственный исполненный исходный ID — `1008009413223697`.

События, пропущенные до установки наблюдателя, нельзя восстановить из этого кеша. Старый ордер не объявляется исполненным по наличию другой позиции. Пользователь сообщил, что прежнюю позицию закрыл самостоятельно; его журнал ручного управления сохранён. Отдельная тестовая позиция закрылась вне торгового журнала бота, её подтверждение использовано только для проверки чтения.

Windows-пакет проверен по manifest/SHA-512 и совпадению всех 37 runtime-модулей и 70 статических файлов со сборкой. Установщик — 95 579 645 байт. Запуск готового ASAR в отдельном временном профиле подтвердил загрузку preload и экрана входа при неактивной торговле. Локальный пользовательский экземпляр обновлён до 0.1.13 и открыт в окне `Hedge LBank · Local` с сохранённым журналом ручного управления.
