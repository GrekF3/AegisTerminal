# 0.1.10 — исправления обновлений и LBank

Windows x64, локальная сборка 2026-09-07. В Stable/Beta не опубликована, установленное приложение и его профиль не заменялись.

## Обновления

- Исправлен переход на полную загрузку из-за некорректных multipart Range-заголовков сервера. Используются поддерживаемые одиночные Range; контроль SHA-512 и полная загрузка при отсутствии/повреждении кэша сохранены.
- Прогресс на старте и в настройках показывает настоящие имена установщика и blockmap, этап, полученные байты, скорость, повторно используемый объём и причину полной загрузки.
- Библиотеки сборки Next/React/шрифтов перенесены в devDependencies. В установщик входят готовый статический интерфейс и три прямые зависимости Electron: electron-updater, https-proxy-agent, socks-proxy-agent.
- Реальная проверка существующего обновления 0.1.8 → 0.1.9 по HTTPS: 41 118 608 байт вместо 164 519 576, 28 запросов, SHA-512 восстановленного файла совпал. Это проверка скачивания, не автоматической установки. Первый переход со старого клиента ещё может потребовать полный пакет.

## LBank и торговый цикл

- Ошибка Post-Only 187/188 считается подтверждённым отказом: исходная лимитка пересчитывается по свежему стакану в пределах таймаута входа. Неизвестный результат отправки не разрешает новую заявку.
- Статус сверяется по точному ID и символу в активных ордерах, постраничной истории и отдельных Trade-исполнениях. Полные исполнения с уникальными TradeID могут подтвердить результат до появления в истории; отсутствие строк не означает отмену. Trade-путь включён только для проверенного множителя контракта 1.
- После первоначальных 15 секунд ожидания истории непрерывная сессия продолжает фоновую сверку до 5 минут, затем требует проверки, если биржа так и не дала результата. Другие монеты продолжают получать проверки PnL. Новые входы разрешаются только после закрытия и учёта подтверждённого предыдущего цикла.
- Закрытие поддерживает несколько собственных позиций и отдельные объёмы по маршрутам TradeUnitID/PosiDirection. Принятые закрывающие заявки сверяются до отправки оставшейся части. Нельзя закрыть копируемую позицию или неоднозначную строку.
- Stop продолжает сверку принятых закрытий и не запускает следующий цикл. Известную лимитку можно попытаться отменить даже при отказе метода чтения; без конечного статуса замена не отправляется.
- Новый Start ждёт завершения запросов прежней сессии: запоздавший preflight не может открыть старую монету после Stop.
- HTTP 403 распознаётся как отказ сервера, а не ошибка JSON. Добавлены JSON-заголовки, строгая проверка USDT-баланса, обработка обрыва ответа и Retry-After. Для отказа приватного API доступно понятное указание на поддерживаемое подключение Undetectable. Доступ с пользовательским API-ключом не проверялся и не объявляется восстановленным.

## Проверка и ограничения

Все 206 backend-тестов пройдены. Регрессии покрывают задержанную историю, неопределённые подтверждения, частичные исполнения, запрет дублей, закрытие нескольких позиций, конкурентный Stop, повторный вход и мониторинг другой монеты во время сверки. Проверены TypeScript, production-сборка интерфейса и отображение прогресса при ширине 1280/420 px.

Установщик — 95 572 539 байт против 164 519 576 байт в 0.1.9 (уменьшение примерно на 42%). ASAR — 6 999 798 байт против 241 842 903. Все 35 Electron runtime-файлов в ASAR совпали с исходниками, production-пакет не содержит Next/React/SWC/Sharp, тестов и пользовательских ключей. `node scripts/verify-release.cjs` проверяет архив, манифест и контрольные суммы.

Упакованный ASAR запущен с отдельным пустым временным профилем. После React hydration подтверждены preload bridge, локальный file-протокол, экран авторизации, поле ключа, canvas, отсутствие активного хеджа и завершение изолированной проверки updater. Проверка не устанавливала приложение и не читала пользовательские настройки.

SHA-256 установщика: `2c27a84afe7b092851d860abc527674b4c18820438bba25f09a25039dc75aab9`.

Новый SDK прочитал живой проблемный ордер `1008009351765676`: ETHUSDT, FILLED, 0.04 ETH, средняя цена 2495.9; Trade-источник независимо подтвердил тот же объём и цену. Реальных заявок и изменений плеча при разработке не отправлялось. Старые незавершённые журналы после перезапуска по-прежнему требуют сверки исходных подключений.

Сбои биржи, недоступность профиля и неподтверждённые результаты не маскируются под успешную торговлю. macOS-сборка и установка через production updater этим выпуском не проверены.
