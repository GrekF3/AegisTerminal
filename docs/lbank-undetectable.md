# LBank Futures · Undetectable

Опубликовано в Stable 0.1.9, 2026-09-07. Установленное приложение вручную не обновлялось и не перезапускалось; пользователь проверяет штатный updater самостоятельно.

Изменения 0.1.10 собраны локально, публикация ещё не выполнена. Подробности и границы проверки: [0.1.10](./releases/0.1.10.md).

### Сверка завершённых ордеров

`/cfd/query/v1.0/Order` возвращает количество контрактов, а `/cfd/order/v1/historyAllOrderPage` — количество базовой монеты. История нормализуется без повторного умножения на `volumeMultiple`. Подтверждено чтением реального закрытия BTC `1008009336339177` (FILLED, 0.0062 BTC) и отмены ETH `1008009337950148` (CANCELED, исполнено 0). Ордер сопоставляется по точному ID и символу, отсутствие строки не считается исполнением или отменой.

Во время перехода заявки в историю ядро до 15 секунд повторяет только чтение с интервалом 0.5 секунды. Затем непрерывная сессия продолжает сверку в фоне до 5 минут, блокируя новые входы и сохраняя контроль PnL остальных монет. После подтверждения закрывает только собственный оставшийся объём и продолжает новые циклы; при пользовательском Stop завершает остановку без нового входа. Если подтверждения так и нет, журнал остаётся незавершённым и требует проверки. Подтверждённые конечные состояния не отменяются повторно.

Дополнительный источник `/cfd/query/v1.0/Trade` подтверждает полный объём по точным OrderSysID, InstrumentID и уникальным TradeID. Частичная сделка не доказывает отмену остатка. Этот источник проверен на контрактах с `volumeMultiple=1`; остальные используют активные заявки и историю. Новый SDK подтвердил проблемный ETH-ордер `1008009351765676` чтением живого профиля, без торговых команд.

Закрытие нескольких собственных строк строится как план отдельных объёмов и маршрутов `TradeUnitID + PosiDirection`. Перед каждой отправкой повторно проверяются позиция и свободный ClosePosition. Копируемые позиции исключаются. Строки с одинаковым маршрутом, которые SDK не позволяет однозначно выбрать, отклоняются. Отказы Post-Only 187/188 приводят к свежему расчёту цены только после подтверждённого отказа без исполнения.

## Подключение

LBank → «Undetectable · CDP» → «Найти профили» → выбор из списка. Поиск внутри списка фильтрует имя или ID сразу, без дополнительных API-запросов. Local API использует стандартный локальный адрес Undetectable автоматически; поля адреса нет. Профиль пользователь запускает самостоятельно. При подключении открывается Futures-вкладка, если её ещё нет; несколько Futures-вкладок одновременно требуют оставить одну.

Сохранённый профиль **не подключается при запуске приложения**. Отключение отсоединяет только CDP-транспорт, не закрывает браузер. Прокси остаётся настройкой выбранного профиля, токены и cookie из него не экспортируются. Ответ после отменённого подключения не может восстановить его.

## Торговый интерфейс

- Чтение баланса кошелька USDT, позиций и обычных/условных ордеров; неизвестные поля не заменяются фиктивными нулями. Для линейных контрактов плавающий PnL рассчитан из mark price, entry price и базового количества.
- Спецификации контрактов, торговые рынки и комиссии берутся из `/cfd/agg/v1/instrument` внутри SDK страницы. Количество базового актива = контрактный объём × `volumeMultiple`.
- Стакан запрашивается дважды через `SendQryMarketOrder`, явно с `Direction=0` и `Direction=1`. Вызов без направления возвращает только одну сторону. Пересечённый/неполный стакан отклоняется.
- Цена начала UTC-дня берётся из первой сегодняшней свечи `KLinelst`, а не из rolling 24h open.
- Плечо: `SendQryLeverage` → при необходимости `setMultiLeverage` → обязательное повторное чтение обеих сторон.
- Открытие: `SendOrderInsert`, LIMIT = `OrderPriceType=0`, MARKET = `4`; `OrderType=0/1`, Post-Only = `OrderType=3` (ONLY_MAKER). Закрытие — противоположная сторона и `OffsetFlag=1`, с проверкой доступного ClosePosition и точным TradeUnitID позиции внутри страницы. Новая последовательность входа: [adaptive-entry.md](./adaptive-entry.md).
- Отмена: `SendOrderAction` с точным OrderSysID. Подтверждение отмены требует отдельного чтения статуса. Cancel-all не используется.
- Статус: активные ордера, затем поиск точного ID в постраничной истории. Строковые ID не округляются; неточный числовой ID отклоняется. Принятие заявки не считается исполнением.
- Перед private-операциями проверяется хеш владельца счёта, зафиксированного при ручном подключении. Смена аккаунта внутри профиля требует вернуть исходный аккаунт/сверить сессию.
- Неизвестное подтверждение или таймаут не запускают слепой повтор. Повтор одного client intention дедуплицируется; сам client intention не выдаётся за подтверждённый серверный ID. Просроченные расчёты не начинают новый write.

## Проверка

### Приоритет исполнения ЦЕЛЕВОЙ ноги

Для нового execution v3 LBank в роли ЦЕЛЕВОЙ всегда получает MARKET/FAK сразу
после подтверждённого исполнения ИСХОДНОЙ. Вторая maker-попытка, ожидание 1,5 с и
цикл отмены для LBank-цели отключены. Перед исходной заявкой повторно проверяется
свежая глубина LBank, а несовместимый минимальный шаг частичного исполнения
блокируется до любых ордеров.

Если MARKET завершился подтверждённым частичным исполнением, приложение отправляет
только точный остаток и не более двух дополнительных попыток. Новый запрос возможен
только после терминального статуса предыдущего; UNKNOWN сохраняется в журнале и
блокирует повтор. Дублирующая проверка владельца перед LBank write удалена: остаётся
одна свежая проверка непосредственно перед отправкой, поэтому общий лимитер больше
не добавляет лишний секундный интервал после исполнения ИСХОДНОЙ.

### Потеря ответа CDP

Команды удерживаются сильной ссылкой внутри исходной вкладки до завершения;
нормализованные ответы торговых команд сохраняются в журнале вкладки. При ошибке
CDP адаптер читает ответ того же запроса, не повторяя `SendOrderInsert`. Повторное
чтение по исходному intention может восстановить точный `OrderSysID`; движок
сохраняет его в торговом журнале до следующих действий. Подтверждённый отказ до
отправки не превращается в UNKNOWN из-за потери транспорта.

Журнал привязан к CDP-сессии и владельцу. Отсутствующий ответ, смена вкладки,
разрыв соединения или несовпадение владельца не дают права повторно отправлять
ордер. Перезапуск/новое подключение не считается подтверждением старой заявки.
Старые неизвестные заявки, созданные до этого исправления, не имеют receipt:
пустые позиции/ордера сами по себе не снимают их блокировку.

Ошибки протокола показывают метод, код и известную безопасную причину (например,
потерю контекста или освобождение Promise), без исходного кода, URL, cookies или
сырых данных ошибки. У старого сообщения «CDP: запрос не выполнен» исходные
код/причина не сохранялись, поэтому задним числом установить их нельзя.

Регрессии покрывают потерю acknowledgement, восстановление отказа до отправки,
сверку точного ID после временной недоступности receipt, потерю контекста,
дедупликацию и сохранение незавершённых команд при очистке старых read-receipts.

Обновление 429: общий in-flight/короткий кэш чтений для счёта, предпросмотра и
мониторинга в одной ручной CDP-сессии. Балансы и позиции опрашиваются раз в секунду,
фоновые обычные/условные ордера — раз в 5 секунд. Подтверждение исполнения не
использует завершённый кэш статусов/истории. Перед writes идентификация и проверки
читаются заново; после writes кэш сбрасывается, запоздалые старые снимки отклоняются.
HTTP 429 включает общую паузу с Retry-After/увеличивающейся задержкой. Предпросмотр
после неё повторяется без запуска торговли; ордера никогда не пересылаются автоматически.

На живом профиле проверены только **read-only** операции, в том числе через Node runtime самого Electron: баланс, пустые позиции/ордера, 812 рынков, обе стороны BTC-стакана, реальные шаги/минимумы, UTC open и персональные комиссии. Отсоединение требует повторного ручного подключения.

Локальные fixtures проверяют открытие, частичные исполнения, отмену, закрытие, LBank как target LIMIT и source MARKET, права на writes, смену владельца, неизвестный acknowledgement, дедупликацию, большие ID и полный position TP/SL по mark price через `SendTriggerOrderInsert`. Реальные ордера, TP/SL и изменения плеча в ходе разработки **не отправлялись**: успешное исполнение на реальном счёте этими тестами не подтверждено.

Внутренний SDK сайта может меняться. Методы находятся по точным endpoint-путям; несовместимость вызывает ошибку, а не подмену обычными API-ключами. Официальный API-режим LBank сохранён отдельно; новые lifecycle-методы относятся к Undetectable, не к старому official mode.

Источники: [Undetectable Local API](https://docs.undetectable.io/api/) и клиентский SDK [LBank Futures](https://www.lbank.com/futures/btcusdt), проверены 2026-09-07. Диагностические скрипты `output/` не входят в пакет приложения.
