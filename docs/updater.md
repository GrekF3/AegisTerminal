# Дифференциальные обновления

## Причина полной загрузки

Проверка 2026-09-07 выявила несовместимый ответ публичного сервера на запрос
нескольких HTTP Range. Сервер отдаёт multipart-тело с
`Content-Type: application/octet-stream`, а значение
`multipart/byteranges; boundary=...` помещает в `Content-Range`.
Установленный `electron-updater` 6.8.9 ожидает multipart в `Content-Type`;
из-за этого дифференциальная загрузка завершается ошибкой и библиотека скачивает
весь установщик. Одиночный Range возвращает корректный HTTP 206.

`electron/update-status.cjs` формирует generic feed с
`useMultipleRangeRequest: false`. Библиотека скачивает только изменённые блоки,
копирует остальные из сохранённого установщика и проверяет SHA-512 собранного
файла. Каналы Stable и Beta по-прежнему разделены каталогами.

## Что показывает приложение

- Подготовка: реальные имена карт изменений `.blockmap`, использованных при сравнении.
- Загрузка: имя скачиваемого `.exe` (или `.zip` на macOS), полученные/нужные
  сетевые байты, скорость и объём, повторно используемый из локальной копии.
- Проверка: после получения всех байт приложение ждёт штатной проверки и
  события `update-downloaded`; одни только 100% не означают готовность.
- Резервная полная загрузка: её причина и новый полный объём видны пользователю.
- Проверенный скачанный пакет повторно используется из кэша.

Та же информация доступна в разделе «Обновления» после входа. В журнал
поддержки сохраняются диагностические сообщения updater и причины fallback,
без многословного лога каждого блока. Имена отдельных файлов внутри ASAR/NSIS
не выдумываются: транспорт обновляет блоки установщика, а не эти файлы по одному.

## Проверка

`node --test electron/update-status.test.cjs`: 7 проверок. Используется настоящий
`NsisUpdater` из установленной зависимости и локальный HTTP-сервер: загрузка
только изменённых диапазонов, проверка конечного SHA-512, повторное использование
готового пакета, отсутствие/повреждение локального кэша, отказ при повреждении
полной загрузки, имена файлов и сброс прогресса при fallback.

Отдельная проверка с публичным сервером действительно собрала 0.1.9 из локального
установщика 0.1.8. Получено 41 118 608 байт за 28 одиночных Range-запросов вместо
164 519 576 байт полного пакета. Повторно использовано 123 400 968 байт, то есть
примерно 75%. Конечный SHA-512 совпал с опубликованным установщиком. Время этого
измерения — 19,9 секунды; будущая скорость зависит от сети и размера изменений.
Никаких установок, перезапусков или изменений профиля эта проверка не делает.

Typecheck пройден. Экран запуска, карты изменений, fallback и блок настроек
проверены в настоящем браузере при ширине 1280 и 420 пикселей с изолированным
bridge. В изменённых блоках нет горизонтального переполнения; интервалы между
соседними группами 12–18 пикселей. Снимки: `output/playwright/updater-*.png`.

## Условия выпуска

Нужно сохранять версионные установщики и `.blockmap` в каталоге каждого канала;
`latest.yml` публикуется после самих файлов. Для исправленного клиента достаточно
поддержки одиночных Range-запросов. При отсутствии или повреждении кэша, отсутствии
карты старой версии либо отказе Range библиотека безопасно скачает полный пакет.
Проверка целостности остаётся обязательной.

Уже установленная 0.1.9 получит исправление только после перехода на новую версию:
сам переход с прежним updater ещё может скачать полный установщик. Экономия
проверена для 0.1.8 → 0.1.9 и не является обещанием такого же процента в каждом
будущем релизе. Исправление не сокращает время распаковки и работы NSIS.

Windows-путь проверен. Текущая конфигурация macOS по-прежнему выпускает только
DMG; для отдельного рабочего macOS auto-update релиза понадобятся ZIP-артефакт
и подходящая подпись. В рамках этого исправления macOS-релиз не создавался.
