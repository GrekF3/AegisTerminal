# Автоматизированный хедж

## Локальная защищённая сессия — 2026-09-12

Поле процента теперь задаёт **общую цель переноса на ЦЕЛЕВУЮ** относительно указанной общей маржи. Маржа на каждой бирже делится поровну между выбранными монетами. Отдельный цикл использует автоматически уменьшенный безопасный диапазон, чтобы стоп исходной ноги не оказался у расчётной ликвидации; комиссии входа/выхода входят в оценку. Циклы продолжаются, пока накопленный net PnL ЦЕЛЕВОЙ не достигнет общей цели либо не сработает лимит лузов.

После равного подтверждённого входа приложение создаёт на **обеих** биржах серверный reduce-only TP/SL полного объёма по mark price и проверяет ID, объём и обе цены. Только после двух подтверждений пара переходит в мониторинг. LBank использует `SendTriggerOrderInsert` для position TP/SL; Bybit — связанный position `Trading Stop` в режиме `Full` с рыночным исполнением обеих ветвей. Bybit дополнительно сверяет `positionIdx`, сторону закрытия и две внутренние условные заявки. При неизвестном результате TP/SL повторная отправка запрещена до точной сверки.

Короткие пропуски PnL показываются как синхронизация, без ошибки/звука. После 15 секунд — предупреждение. Отсутствующий PnL источника не блокирует закрытие по известному PnL цели. Новые входы ждут восстановления данных.

«Стоп! Точно стоп!» показывает подтверждённый прогресс: сверка и отмена своих заявок → закрытие своих объёмов → подтверждение исполнения по каждой бирже/монете. Повторное автоматическое закрытие заблокировано на время операции. Кнопка ручной остановки остаётся доступной и может прервать ожидание.

Начиная с локальной 0.1.11 «Я закрою позиции сам» сразу останавливает автоматизацию без запросов к биржам, отмен и закрытий. Undetectable, вход на сервер и восстановление credentials для этого не нужны. Позиции и заявки остаются на биржах под управлением пользователя; журнал сохраняется отдельно в `manual-stops`. Уже переданная в адаптер операция может завершиться, её пришедший ответ сохраняется без следующей сверки/заявки. Остановка не ждёт эту операцию; новый Start дождётся завершения прежних запросов.

Начиная с локальной 0.1.12 сама верхняя кнопка «Стоп» немедленно фиксирует `botStopped=true / active=false` до выбора дальнейшего действия. Диалог показывает уже остановленного бота. Закрытие позиций запускается отдельным явным действием; его состояние хранится в `closeStatus` и `closeError`. Недоступный Undetectable, ошибка авторизации, неизвестный исход LBank-заявки и поздний ответ не возвращают стратегию в работу. Можно закрыть диалог, оставить позиции под ручным управлением или повторить подтверждение закрытия. После перезапуска остановленная сессия остаётся остановленной; неопределённые заявки сохраняются и блокируют новый вход до разрешения ситуации либо выбора ручного управления. Полная запись — [releases/0.1.12.md](./releases/0.1.12.md).

Локальная 0.1.13 сохраняет точные статусы из приватного потока LBank до удаления исполненной заявки из активного списка. Терминальное подтверждение используется независимо от задержки REST-истории. После временной задержки подтверждения входа сессия достраивает только недостающий подтверждённый объём второй ноги и сохраняет текущий хедж. Пользовательский Stop запрещает такое продолжение; уже начатое закрытие остаётся закрытием. Подробности и границы живой проверки — [releases/0.1.13.md](./releases/0.1.13.md).

Новые входы разрешены только паре адаптеров, которые оба подтверждают серверный TP/SL; приоритетная полностью реализованная связка — LBank ↔ Bybit. Для LBank плечо ограничено 20x и требуется isolated-маржа на обеих биржах. Настройка 100% не ставит стоп у ликвидации: движок делит общую цель на безопасные циклы с резервом. Это снижает риск, но не является гарантией прибыли или исполнения при сбое самой биржи.

Новый вход v2: лимитка на источнике следует за его bid/ask; при поддержке Post-Only на обеих биржах целевая тоже пробует maker до 1,5 секунды, затем подтверждённый остаток добирается маркетом. Если maker на обеих не поддерживается — источник LIMIT, цель MARKET. Полный протокол, ограничения и совместимость журнала: [adaptive-entry.md](./adaptive-entry.md).

Локальный execution v3 делает LBank приоритетной ЦЕЛЕВОЙ ногой: после fill ИСХОДНОЙ
она отправляется MARKET/FAK без второй maker-паузы. Перед созданием исходного риска
повторно проверяются свежая целевая глубина и совместимость минимального частичного
объёма. Подтверждённый частичный MARKET добирается ограниченно и только после
терминального статуса; неизвестный исход по-прежнему никогда не пересылается.

Непрерывная сессия заменяет одноразовый запуск: целевая сторона по текущему UTC-дню, исходная противоположно, закрытие по ±порогу маржи отдельной монеты и автоматический следующий цикл. Лимит лузов общий за сессию, 0 — без ограничения; подробности в `beta-hedge.md`. Нижеописанное поведение релиза 0.1.8 сохранено для исторического контекста и не описывает новые непрерывные циклы.

Добавлен полный интерфейс торгового адаптера LBank **Undetectable · CDP**: ручное подключение, чтение, спецификации, персональные комиссии, настройка плеча, LIMIT/MARKET, статусы, отмена и закрытие позиции. В форме только поиск профилей и список с фильтрацией по имени/ID. Автоподключение профиля отключено. См. `lbank-undetectable.md` для протокола и границ проверки.

## Пользовательский сценарий

Две биржи → одна или несколько общих USDT-монет → плечо каждой монеты → запуск.
Сохранённая общая маржа **на одну биржу** делится поровну между выбранными монетами.
Например, 100 USDT и 4 монеты дают по 25 USDT маржи на монету на каждой бирже.
Плечо меняет номинальный объём, не распределение маржи. Биржевые шаги округляют объём вниз до общего допустимого количества базового актива.

Перед запуском проверяются балансы, общие шаги и минимумы, доступная ликвидность, отсутствие существующих позиций/заявок по выбранным инструментам. Плечо на обеих биржах задаётся для всей корзины до первого ордера. Изменение ключей и пары активного хеджа заблокировано.

Начиная с 0.1.8 пользовательский запуск всегда реальный: старый флаг симуляции в настройках игнорируется, переключатель убран. Сам запуск приложения или установка обновления не открывают ордеров. Внутренний dryRun остаётся только для проверки торгового ядра без сети.

В 0.1.9 целевая сторона открывается по внутридневному тренду, исходная — противоположно. Источник использует переставляемый LIMIT; цель пробует maker до 1,5 секунды при поддержке Post-Only обеими биржами, иначе использует MARKET. Принятие заявки не считается её исполнением. Неизвестный результат запроса не приводит к повторной отправке. Стоп отменяет остатки, перечитывает исполнения и закрывает только объём этого цикла; режим «только приложение» оставляет позиции пользователю.

## Синхронизация и отображение

- Балансы и позиции опрашиваются раз в секунду, независимо друг от друга, без пересекающихся запросов одного типа. Сетевые ошибки увеличивают интервал повторов до 30 секунд; последнее значение остаётся с отметкой задержки.
- Открытые обычные ордера Binance опрашиваются раз в 10 секунд из-за веса API-запроса; остальные — раз в секунду. Это не замедляет контроль собственной лимитки торговым ядром.
- «Статус» показывает позиции, обычные открытые ордера, исполнения хеджа, направление, объём, маржу, цены, PnL, ликвидацию. Неизвестные числовые поля обозначаются тире.
- Балансы используют анимацию прокрутки цифр без пересоздания DOM на каждом обновлении. Уменьшение анимаций ОС учитывается.
- Интерфейс показывает накопленный net PnL ЦЕЛЕВОЙ и общую цель в USDT. Пополнения счёта и посторонние позиции не считаются результатом хеджа.
- Комиссии оцениваются по персональным maker/taker-ставкам и вычитаются из результата. Итог остаётся предварительным до биржевой сверки funding и фактических комиссий исполнения.

## Восстановление и ограничения

Каждое намерение отправить ордер или серверный TP/SL записывается в `hedge-session.json` до сетевого вызова. После перезапуска полностью защищённая непрерывная сессия сначала повторно проверяет обе серверные защиты и только затем продолжает мониторинг/новые циклы. Старый или незакрытый журнал без двух подтверждённых защит остаётся в `recovery_required` и не отправляет новые входы. API-секреты в журнал не записываются; сопоставление подключения использует SHA-256.

LBank: полный торговый цикл реализован в режиме Undetectable · CDP, который требует ручного подключения запущенного профиля. Старый official API mode не получил этот lifecycle автоматически; его ограничения остаются отдельными. Подробности — [lbank-undetectable.md](./lbank-undetectable.md).

MEXC: автоматическое плечо пока только isolated. Для большого числа открытых заявок некоторые адаптеры останавливают проверку, если API мог обрезать страницу. Bybit Full position TP/SL и LBank position TP/SL входят в снимок открытых ордеров; полная история закрытых сделок отдельно пока не синхронизируется. Пользовательские позиции/ордера, открытые вручную одновременно с работой бота, могут потребовать ручной сверки.

## Ошибки бирж и подтверждение закрытия

Для Binance, Bybit, OKX, Bitget, MEXC и Gate.io ответы API проходят через общую типизацию: неизвестный исход исполнения, временная ошибка/лимит запросов, авторизация, недостаточная маржа, ликвидация, конфликт режима позиции, риск-лимит, отсутствующая позиция, отсутствующий или уже завершённый ордер, дубликат и Post-Only rejection. Исходный код биржи сохраняется отдельно в `exchangeCode`; неизвестный новый код не считается безопасным для повторной отправки и остаётся fail-closed. LBank в эту таблицу намеренно не включён: его фьючерсный browser lifecycle обслуживается отдельным адаптером.

Коды «позиции нет» сами по себе не подтверждают закрытие. Перед каждым reduce-only market close и после него ядро читает отдельный снимок позиций точного symbol/side. OKX `51169`, Binance `-2024`, Bybit `110034`, Bitget `25227`, MEXC `2009` и Gate `POSITION_EMPTY` завершают закрытие только при нулевом снимке. Если позиция осталась, повторный ордер не отправляется. Если позиция исчезла из-за серверного TP/SL, ликвидации, ADL или внешнего действия, факт закрытия записывается из снимка; неизвестная цена выхода помечается `provisionalPrice`, поэтому PnL остаётся предварительным.

При повторном закрытии остановленной сессии приложение сначала получает свежие позиции и все открытые заявки обеих бирж по символам сессии. Если оба полных снимка пусты, очистка подтверждается без новых cancel/reduce-only запросов, журнал архивируется и интерфейс возвращается в исходное состояние. Ошибка закрытия, уже показанная до перезапуска приложения, не повторяется как новая; блокировка безопасности остаётся до свежей сверки. Локальная остановка очереди LBank завершается до начала этой сверки, поэтому новые запросы закрытия не могут быть отменены старым stop-fence.

## Проверка

`npm run test:backend` — модульные тесты без реальной торговли.
`npm run build:web` — production static export.
`npm run dev:web` — интерфейс Next.js на localhost; приватные биржевые API работают только через Electron.
`npm run dev` — локальный desktop-режим (без установки релиза).

`npm run dev:desktop` — открыть только Electron, если Next.js уже работает на порту 3000.
`npm run dev:import-profile` — первоначально скопировать подключения из установленного приложения в отдельный профиль `hedge-lbank-dev`. Отказывается перезаписывать существующие файлы. Сохраняет зашифрованные `credentials.bin`, системный ключ из `Local State` и существующий `device.id`; не переносит торговый журнал. В новой копии автообновление и автозапуск выключены; торговля запускается пользователем в реальном режиме, как в релизе. Профиль установленного приложения не меняется.

Локальная проверка 2026-09-06: существующие OKX и Gate.io подключения успешно расшифрованы средствами Electron и проверены чтением реальных балансов и позиций. Исправлен недопустимый limit=1000 в Gate positions; без limit API возвращает все позиции. Реальных заявок эта проверка не отправляет.

Browser QA использует изолированный bridge только в `output/playwright/setup-hedge-fixture.js`, не импортируемый приложением. Тестовые ключи и балансы не являются fallback приложения. Проверены размеры 1320, 1024, 640 px, поиск, выбор монет, отдельное плечо, сохранение маржи, таблицы и стабильность DOM цифр.

Реальные ордера в ходе разработки не отправлялись. Установка пользователю автоматически средствами разработки не выполняется: обновление остаётся за штатным updater приложения.

Исторический релиз 0.1.8 опубликован 2026-09-06 в Windows x64 каналы Beta и Stable: 68 тестов, production-сборка, браузерная проверка через изолированный bridge. В том релизе автоматический LBank ещё был заблокирован. Начиная с 0.1.9 режим Undetectable · CDP доступен; актуальная запись выпуска приведена выше. Установленное приложение средствами разработки не перезапускается, полный цикл установки пользователь проверяет самостоятельно.

## Сверенные спецификации

- [Binance Futures Error Codes](https://developers.binance.com/docs/derivatives/usds-margined-futures/error-code): неизвестный исход `-1006/-1007`, позиции/маржа, режимы и Post-Only `-5022`.
- [Bybit V5 Error Codes](https://bybit-exchange.github.io/docs/v5/error): статусы ордера, позиция, маржа, режим и риск-лимиты.
- [OKX Error Codes](https://app.okx.com/docs-v5/en/#error-code): `51169`, таймаут с неизвестным исходом `50004`, режимы и ограничения.
- [Bitget REST Error Codes](https://www.bitget.com/docs/uta/error-code/restapi) и [Place Order](https://www.bitget.com/api-doc/classic/contract/trade/Place-Order): коды позиции/маржи и обязательная сверка `clientOid` для неизвестного результата.
- [MEXC Contract API](https://mexcdevelop.github.io/apidocs/contract_v1_en/#error-code): системные, permission, position и order-коды Contract V1.
- [Gate API v4 label list](https://www.gate.com/docs/developers/apiv4/en/#label-list): futures labels позиции, ордера, маржи, ликвидации и Post-Only.

- [Binance Account V3](https://developers.binance.com/docs/derivatives/usds-margined-futures/account/rest-api/Account-Information-V3): USDT marginBalance включает весь unrealized PnL, не только cross.
- [Binance Open Orders](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Current-All-Open-Orders): вес без symbol — 40.
- [Gate Futures](https://www.gate.com/docs/developers/apiv4/en/futures/): множители контрактов, позиции и query-параметры плеча.
- [MEXC Order by External ID](https://www.mexc.com/api-docs/futures/account-and-trading-endpoints/get-order-by-external-id): точный внешний ID и состояния ордеров.
- [Bybit Positions](https://bybit-exchange.github.io/docs/v5/position): пагинация, `positionIdx`, полный объём и текущие TP/SL.
- [Bybit Trading Stop](https://bybit-exchange.github.io/docs/v5/position/trading-stop): связанный Full position TP/SL, Mark Price и рыночное исполнение.
- [Bybit Open Orders](https://bybit-exchange.github.io/docs/v5/order/open-order): сверка внутренних TP/SL заявок и их точных ID.
- [OKX API](https://www.okx.com/docs-v5/en/): размеры контрактов, режимы позиций и плечо.
- [Bitget Leverage](https://www.bitget.com/api-doc/classic/contract/account/Change-Leverage): настройки плеча USDT-FUTURES.
